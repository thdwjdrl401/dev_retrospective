# 개발 회고

회사에서 수행한 프로젝트의 코드 자체는 공개할 수 없어, 실제로 담당했던 개발·운영 작업을 기술 회고 형태로 정리한 레포지토리입니다.

약 20만 사용자 규모의 공공 서비스를 포함해 앱, API 서버, 관리자 웹의 개발과 운영을 담당했고, 그 과정에서 겪은 보안, 성능, 데이터 정합성, 인증/인가, 외부 시스템 연계 문제를 프로젝트별로 정리했습니다.

각 문서는 실제 작업 내용을 기준으로 문제 상황, 원인, 적용한 방법, 결과, 당시 판단과 한계를 기록했습니다.

**기술 스택**: Java, Spring Boot, JPA, Flutter/Dart, MySQL, GitLab

---

## 주요 기술 경험

프로젝트에서 직접 구현하거나 개선한 내용을 기술 영역별로 정리했습니다. 상세한 원인 분석과 구현 내용은 각 프로젝트 문서에서 확인할 수 있습니다.

* **영속성 / 트랜잭션**: 복호화 과정에서 managed 엔티티가 변경되면서 JPA Dirty Checking으로 평문이 DB에 재저장되는 문제를 추적하고 `flush -> detach` 순서로 수정
  [moiso](./moiso/)

* **암호화 / 개인정보 보호**: 기존 Base64 첨부파일을 AES 방식으로 점진적으로 전환하기 위해 매직 값 기반 포맷 판별 적용, 로그인 비밀번호 RSA 전처리, 주민등록번호 메모리 평문 잔존 문제를 메모리 덤프로 재현하고 입력부터 전송까지 처리 구조 개선
  [moiso](./moiso/)

* **인증 / 인가**: 로그인 여부만 확인하던 REST 엔드포인트에 역할 기반 인가 적용, 첨부파일 대상과 사용자 역할을 기준으로 접근 제어 구현, 인증이 없던 앱 API에 JWT 기반 인증 적용
  [moiso](./moiso/) / [carsub](./carsub/)

* **성능 / 대량 데이터 처리**: 근무상황표 조회의 N+1을 일괄 조회와 요청 단위 Map 인덱싱으로 개선해 응답 시간을 10초 이상에서 0.5초 이내로 단축, 대량 엑셀 생성에 SXSSF 스트리밍과 비동기 처리 적용
  [moiso](./moiso/)

* **외부 시스템 연계**: 외부 시스템의 코드 체계와 내부 데이터 모델을 연결하기 위해 뷰 테이블과 코드 매핑 구조를 적용하고, 변경 가능성이 높은 매핑 값은 DB에서 관리
  [duksung_rnd](./duksung_rnd/)

* **운영 자동화**: 반복적으로 수행하던 DB 백업과 서비스 상태 확인 작업을 자동화하고, SSH 기반 원격 백업과 상태 변경 알림 기능 구현
  [asnet_dashboard](./asnet_dashboard/)

## 작업 방식

프로젝트를 돌아보면 다음과 같은 방식으로 문제를 처리한 경우가 많았습니다.

* **반복되는 운영 작업은 필요에 따라 자동화했습니다.**
  정기 DB 백업이나 데이터 정리처럼 반복적으로 수행하던 작업은 내부 도구로 옮겨 수작업 범위와 작업 오류 가능성을 줄였습니다.
  관련 프로젝트: `asnet_dashboard`, `tomas_assist`

* **운영 중 자주 변경되는 값은 코드와 분리해 관리했습니다.**
  외부 시스템의 코드 매핑이나 기능 노출 정책처럼 변경 가능성이 높은 값은 DB에서 관리해 코드 수정과 재배포 없이 반영할 수 있도록 구성했습니다.

* **운영 데이터의 포맷 변경은 기존 데이터와의 호환성을 우선 확인했습니다.**
  기존 파일을 한 번에 모두 변환하기보다 신규 포맷과 기존 포맷을 함께 처리할 수 있도록 구성했습니다. 첨부파일 암호화 전환에서는 파일 헤더의 매직 값을 기준으로 포맷을 판별했습니다.

* **운영 환경에서는 구현 복잡도뿐 아니라 관리 비용도 함께 고려했습니다.**
  별도 인프라를 추가하면 성능이나 확장성 측면에서 이점이 있더라도 운영 대상과 장애 지점이 함께 증가하기 때문에, 당시 인력과 시스템 규모에 맞춰 적용 범위를 결정했습니다.
